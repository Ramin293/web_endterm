# Endterm — распределение работы OrbitFood

Проект продолжает существующий ресторанный сайт: 8 связанных HTML-страниц, локальные Bootstrap CSS и изображения. До endterm отсутствовали собственный JavaScript, динамический каталог, валидация JavaScript и jQuery. Формы используют браузерную проверку и переход на статические страницы результата. Тема, страницы, навигация и адаптивная основа сохранены.

Имена обоих участников в исходном README не указаны. Перед сдачей впишите настоящие ФИО вместо ролей. Разделение примерно равное по объёму реализации и проверки; защита общая и составляет 40 из 100 баллов.

## Часть 1 — вы — реализовано

- `js/menu-data.js`: массив блюд с ценами, категориями и ссылками, второй массив категорий. Партнёр может использовать каталог для заказа.
- `js/menu.js`: вывод карточек из массива, функции с параметрами и возвращаемыми значениями, циклы `for...of` и `forEach`.
- Поиск по названию и ингредиентам; фильтрация категории; сортировка внутри категории; избранное с добавлением/удалением; режим только избранного; очистка избранного; сброс фильтров.
- Динамическое создание и удаление карточек, обновление текста, классов, aria-атрибутов и состояния кнопок. Обработка пустой выдачи.
- `addEventListener`: `DOMContentLoaded`, `click`, `input`, `change`; используется объект события и делегирование.
- Сохранение избранного в localStorage с обработкой недоступного хранилища; доступные подписи и восстановление фокуса после удаления карточек.
- README с инструкциями проверки и этот план.

Покрывает технические пункты 2, 3, 4 и часть 1 и 7 ТЗ. В пункте 4 `preventDefault()` для управляемой отправки формы реализует партнёр. jQuery здесь намеренно не добавлен: это самостоятельный блок второй части.

## Часть 2 — партнёр — осталось выполнить

### 1. Формы и валидация JavaScript

Создать внешний `js/forms.js` и подключить его только к нужным страницам. Обязательный минимум ТЗ — одна существенная форма; рекомендуем завершить обе существующие формы для цельного UX.

- Бронирование (`reservation.html`): проверять имя после trim (2–60 символов), обязательную корректную дату не в прошлом, выбранное время из списка, гостей целым числом 1–6, длину заметки до 300. Для бронирования сегодня исключать уже прошедшее время; определить и объяснить часовую зону ресторана.
- При необходимости добавить email с label и проверкой формата. Email не обязателен по ТЗ, если другие подходящие правила уже выполнены.
- Заказ (`order.html`): проверять выбор существующего блюда, целое количество 1–6 и допустимое время самовывоза. Использовать числовые цены из `window.OrbitFood.dishes` для живого итога; сначала подключить `menu-data.js`.
- Перехватить `submit` через `addEventListener`, использовать объект события и `preventDefault()`. Включать `noValidate` из JS, чтобы при отключённом JS осталась браузерная проверка.
- Для каждого неверного поля показывать конкретную ошибку рядом с ним, связать её через `aria-describedby`, выставлять `aria-invalid`, фокусировать первое неверное поле. Перепроверять исправленные значения.
- При корректных данных показать заметное сообщение об успешной демо-операции. Не отправлять данные реальному ресторану. Если используете страницы результата, выводить пользовательские значения через `textContent`, не `innerHTML`; прямое открытие без данных не должно сообщать о подтверждённой операции.
- Не записывать персональные данные в URL или постоянное хранилище без необходимости. Обновить устаревшее описание GET-форм в README после изменения поведения.

Приёмка: пустая форма, пробельное имя, вчерашняя дата, прошедшее время сегодня, недопустимые количество/опции, исправление ошибки, успешная отправка без перезагрузки либо с корректной страницей результата. Успех должен явно говорить о демонстрации, а не реальном бронировании.

### 2. jQuery с полезными эффектами

Добавить локальную копию jQuery с лицензией и внешний `js/enhancements.js`; подключать jQuery перед своим файлом. Можно использовать CDN, но тогда исправить обещание офлайн-работы в README и проверить поведение без сети.

Предлагаемые функции на `about.html` и `reservation.html`:

- FAQ с кнопками: селекторы по классу и ID/атрибуту, обработчик `click`; находить блок ответа через `closest()` и `find()`, раскрывать/сворачивать через `slideDown()`/`slideUp()`. Синхронизировать `aria-expanded` и `aria-controls`.
- Подсказка к заметке: обработчик `focusin`/`focusout` или `change` для раскрытия полезного пояснения через `fadeIn()`/`fadeOut()`; связать подсказку с полем. Это второй пользовательский event и второй тип эффекта.
- Учитывать `prefers-reduced-motion`, избегать очереди анимаций через `stop(true, true)`. Содержимое должно оставаться доступным без JS.

Проверить буквально: минимум 2 типа селекторов, 2 метода traversal, 2 пользовательских события jQuery, 2 разных полезных эффекта. Не заменять эти примеры обычным JavaScript: проверяется именно jQuery.
